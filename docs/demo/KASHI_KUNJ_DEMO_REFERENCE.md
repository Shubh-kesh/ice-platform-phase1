# Kashi Kunj — Demo Reference Guide

> Companion to `KASHI_KUNJ_DEMO_RUNBOOK.md`. This document describes the exact
> demo dataset that `backend/app/demo/kashi_kunj.py` produces, with the **real
> values captured from a verified seed** (project code, PO numbers, invoice
> numbers, health verdicts). Use it to answer "why does it show this?" during
> the client meeting.

**IMPORTANT**: every person, vendor, phone number, email and commercial figure
in this dataset is **fictional** and exists only to make the demo look and feel
real. It is generated local-dev data — never production data, never real
customers or real money.

---

## 10. RBAC proof-points (verified by `verify`)

- Admin: full access incl. health, overrides, assignments, finance.
- Procurement: full procurement + finance **read**, cannot approve a PO (403).
- Supervisor: assigned-project access, tasks + site logs; **403 on**
  job-costs, budget, purchase-orders, billing-milestones, invoices.
- Client: project + issued invoices only; **no DRAFT invoices**, no notes in
  the invoice shape; **403 on** health, job-costs, budget, purchase-orders,
  inventory, billing-milestones.

## 11. How it is built (for engineers)

- `backend/app/demo/kashi_kunj.py` — `seed` / `verify` / `reset` / `reseed` /
  `smoke` CLI.
- Every write goes through the **real FastAPI app** (in-process httpx
  ASGITransport, rate limiter disabled like the test suite). Only the bootstrap
  admin and the reset are direct-DB, because the product intentionally has no
  user/project delete endpoints.
- Idempotency keys are used on project/PO/receive/invoice creates; every
  helper checks existence first, so the seed is **idempotent and resumable**.
- Safety: refuses `ENVIRONMENT=production`; requires `ICE_KASHI_DEMO=true` for
  seed/reseed; requires a valid `ICE_KASHI_DEMO_PASSWORD`.
- `reset` removes **only** Kashi-owned rows + the 5 demo vendors; unrelated
  data and the bootstrap admin are never touched. No DROP DATABASE.
