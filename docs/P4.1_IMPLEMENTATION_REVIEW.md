# P4.1 — CI/CD & Automated Quality Gates — Implementation Review

**Status:** IMPLEMENTED, locally verified (not yet committed).
**Date:** Aug 12, 2026.
**Plan:** `docs/PHASE4_IMPLEMENTATION_PLAN.md` §5/P4.1 and §8 (source of truth
for intent; this document records what was actually implemented and verified).

## 1. Implementation summary

P4.1 adds a GitHub Actions workflow that enforces the repository's quality
gates on every pull request and on pushes to the development/main/master
branches. It implements the ROADMAP Phase 4 CI/CD MUST with a
**baseline-delta** design: the pre-existing lint/type findings (Ruff 2, Mypy
10, oxlint 1) are committed as baselines, and CI fails only when a change
introduces a NEW finding — never on the existing debt, and never silently
tolerating new debt.

## 2. Files changed

- `.github/workflows/ci.yml` — new CI workflow.
- `scripts/ci_quality.py` — new shared delta checker (runs a tool, parses its
  findings, compares against a baseline; fails on new findings; fails loudly
  if the tool cannot run).
- `.ci/baseline_ruff.txt` — new baseline (2 pre-existing Ruff F401s).
- `.ci/baseline_mypy.txt` — new baseline (10 pre-existing mypy errors).
- `.ci/baseline_oxlint.txt` — new baseline (1 pre-existing oxlint warning).
- `docs/CURRENT_STATE.md`, `docs/ROADMAP.md`, `docs/SESSION_NOTES.md` — CI

No application/business/auth behavior was modified. No dependency or Docker

## 3. Workflow / jobs created

`.github/workflows/ci.yml`:

- **Job `backend` (ubuntu-latest):**
  1. Checkout (`fetch-depth: 0`, `persist-credentials: false`).
  2. Set up Python 3.12 (pip cache keyed on `backend/requirements-dev.txt`).
  3. `pip install -r requirements-dev.txt`.
  4. Ruff baseline gate.
  5. Mypy baseline gate.
  6. `pytest -q` (full suite, incl. Alembic migration-chain test) against the
     Postgres service.
  7. `git diff --check` against the PR base / prior push.
- **Job `frontend` (ubuntu-latest):**
  1. Checkout (`persist-credentials: false`).
  2. Set up Python 3.12 (shared CI script) + Node 22 (npm cache keyed on
     `frontend/package-lock.json`).
  3. `npm ci`.
  4. `npm run build` (tsc + vite).
  5. oxlint baseline gate.

## 4. Triggers

- `pull_request` (any target).
- `push` to `claude-development`, `main`, or `master`.
- `workflow_dispatch` (manual).

Concurrency: same-ref runs cancel in-progress (fastest feedback).

## 5. Python / Node versions

- Python **3.12** (matches the backend Docker runtime for parity).
- Node **22** (LTS; satisfies Vite 8's `^20.19.0 || >=22.12.0` requirement).
- Actions pinned: `actions/checkout@v4`, `actions/setup-python@v5`,
  `actions/setup-node@v4`.

## 6. Database / service strategy

- Postgres 16 service container with `ice_user`/`ice_pass`/`ice_db` (matching
  the repository's test fixtures); the suite creates/drops `ice_test_db` and
  `ice_migration_test_db` per test — CI never touches a developer database.
- Redis 7 service container (tests do not currently require it; provisioned
  for future rate-limit/observability tests and stack parity).
- The Alembic migration-chain test (`test_migrations.py`) runs its real
  upgrade/downgrade/replay against the service Postgres.
- No production infrastructure is required for CI.

## 7. Quality gates

- Backend: ruff (baseline-aware), mypy (baseline-aware), full `pytest`
  (213 tests incl. migration chain), `git diff --check`.
- Frontend: `npm ci`, `npm run build` (tsc + vite), oxlint (baseline-aware).
- A tool that exits non-zero with **zero** findings is treated as a hard
  failure (prevents a missing/broken tool from passing silently).

## 8. Baseline-error handling

- Baselines live in `.ci/baseline_*.txt` (one stable key per finding).
- `scripts/ci_quality.py` compares current findings vs baseline:
  - All current findings already in baseline → PASS.
  - Any current finding NOT in baseline → FAIL (reports each NEW key).
  - A baseline finding that disappears → reported as RESOLVED (progress),
    never a failure.
- Policy: do not edit a baseline to mask a new error; update it only when a
  finding is genuinely fixed or intentionally re-baselined with approval.

## 9. Security review

- GitHub token: `permissions: contents: read` (least privilege; no write, no
  deployments, no packages).
- `persist-credentials: false` on checkout.
- No secrets referenced anywhere in the workflow; nothing is printed that
  could leak credentials.
- Untrusted PR code runs only on the standard isolated runner with the
  read-only token; no secret injection into job environments.
- Pinned action SHAs are not used (tags `@v4`/`@v5`), a known hardening
  trade-off; noted as a remaining concern for pinning to SHAs if strict supply
  chain control is required.
- No deploy/production steps exist — P4.1 is gate-only.

## 11. Actual CI run result

**Not executed on GitHub.** `gh`/`actionlint` are not installed locally and
running a live workflow requires pushing a branch, which is excluded by this
task's "do not commit/push" constraint. Every gate and the delta logic were
verified locally against the same commands the workflow invokes; a post-approval
push is the only remaining verification step.

## 12. Deliberate-failure verification

- Introduced a NEW unused import (`_ci_temp_test.py`) → ruff gate FAILED
  (exit 1) reporting `app/_ci_temp_test.py:1:F401`. Temp file removed.
- Introduced a NEW type error → mypy gate FAILED (exit 1) reporting the new
  assignment error. Temp file removed.
- Introduced a NEW oxlint warning (`_ci_temp.tsx`) → oxlint gate FAILED
  (exit 1). Temp file removed.
- After cleanup, all three gates pass again at baseline (no leftover files).
